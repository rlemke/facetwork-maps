How to read the rates. A product fails if a data file is missing at the URL the registry records, unreachable, or differs from its recorded checksum or size. Files larger than 20 MB were checked for existence and size only ("size only"), which proves they are not missing or truncated but not that their content is intact. The failure rate is over products that reached a verdict; the interval is a 95% Wilson interval, and the estimate scales the rate to the products that site holds with a checksum. Label files are judged separately (last column), so a stale registry entry for a label is not reported as damaged data. Missing means missing at that URL, not lost: a site that moves its files without the registry being updated produces exactly this. Unreachable and timeout count as failures from here; a site that blocks one client is not the same as a lost file, so read the detail column.

Method

Products are drawn per site by sorting on the data file's MD5 and starting at a random 128-bit value: MD5s are uniformly distributed, so what follows a random point in hash order is an unbiased draw. Products with no recorded MD5 cannot be drawn that way and are counted in the "No checksum" column instead. Every data file of a sampled product is checked, and its label (.xml) file too.
